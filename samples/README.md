# samples —— 为什么这里没有真数据

这个插件靠**四个池子**工作，而那些池子里装的是**你的真实记忆与对话原文**。
把它们提交上来，等于把私人笔记公开。所以本目录只放**结构示例**。

```
topics-data/
├── library.json            记忆池       {"meta":{…}, "topics":[…], "docs":[{i, topic, text, vec}]}
├── mem-multichannel.json   标签池       {"meta":{…}, "entries":[{idx, 通道, 引用, 标签, vec, topic}]}
├── conversations.json      对话池       {"meta":{…}, "docs":[{msg_id, session_id, text, vec}]}
└── mem-important.json      重点记忆池   {"meta":{…}, "entries":[{内容, 重要度, 来源{会话,msg_id,原文锚,索引}, vec}]}
```

## 为什么不能给你一份"能直接跑"的假数据

因为池子里**每条都带一个向量**（512 维浮点数组）。
向量不是能随便编的数字 —— 编出来的向量和文本对不上，检索结果会全是噪声，
反而让人以为"这插件坏了"。

**正确的做法**：用 `pipeline/` 里的脚本，**从你自己的对话生成**池子。
脚本是参考实现（作者自用，路径与流程需要你自己改），核心步骤是：

1. 从宿主的 `state.db` 里取出你要索引的内容（对话原文 / 要点 / 记忆）
2. 调本地向量服务（`service/embed-server.mjs`）算向量
3. 写成上面那四个 JSON 的结构

## 最小的"我能跑起来"路径

1. 起向量服务：`node service/embed-server.mjs 8765`
2. 手写一个**最小记忆池**：10 条你自己编的短句 + 用服务的 `/vector` 接口给每条算一个向量
   （结构照 `library.sample.json`）
3. 打开开关：在插件数据目录建一个空文件 `CANDIDATES_ON`
4. 重启 Hermes，看日志里有没有 `候选表：粗筛门槛 0.42 → …`
5. 然后对着一句和池子里某条相近的话提问，看它有没有被检索出来

> 提醒：**先只放你愿意公开的假内容**。等确认链路通了，再换成真数据 —— 并且
> 确保 `.gitignore` 已经在挡着。
