# pipeline —— 池子是怎么生产出来的

> ⚠️ **本目录故意不放代码。** 原因见下。

## 为什么空着

这套系统的三层里，**插件层**（`memory/topics/`）是可以干净发布的：它只读池子、不生成。
而**生产池子的脚本**是我自用的一批工具（PowerShell + Node + Python 混着），它们里面：

- 写死了我自己的路径与目录结构
- 引用了一批只在我机器上存在的中间产物
- 有些脚本是**一次性的实验脚本**，跑完就废（我自己也没整理）

直接放进来，别人**跑不起来**（还容易被误以为"这就是完整方案"）。所以这里只给**流程**。

## 流程（这是可以照做的部分）

```
你的对话（state.db）
   │
   ├─ 1. 抽取：把要被检索的内容挑出来
   │      · 对话原文 → 会话里被"退场"的轮次
   │      · 记忆条目 → 你已有的记忆库（我的来源是一份人工整理的数据集）
   │
   ├─ 2. 要点化（可选，要调模型）：把内容压成一行带类型标签的要点
   │      例：`【要什么】用户要求…｜原文 #9402036`
   │      这一步生成的要点，就是后来"索引行"和"自动挑重点"的原料
   │
   ├─ 3. 算向量：调 service/embed-server.mjs 的 /vector 接口（本地，零 API 成本）
   │
   └─ 4. 写池：按 samples/README.md 里的四个结构落盘
          library.json / mem-multichannel.json / conversations.json / mem-important.json
```

## 两条经验（踩出来的，别重犯）

1. **去重要在生成端做，别指望插件**。我的池子里相似度 ≥0.85 的成对占 **48%**
   （同一事实存了几十个抄本），插件层去重只认得出 **8.3%**。
2. **要点用"一行 + 类型标签"**，别用长摘要。实测：短句向量干净（自匹配中位 0.886），
   长文糊（最低 0.576，连自己都匹配不上）。

## 想referencing实现的话

我自用的版本叫 `hermes-trim`，核心脚本大致是：

| 脚本 | 干什么 |
|---|---|
| `roll-trim.js` | 判断哪些轮次"退场"（窗口 = N 轮 + 1 缓冲），写 `api_content` |
| `gen-summaries-byids.js` | 调模型把内容压成一行要点 |
| `build_conv_index_v2.py` | 重建对话池 |
| `build_lib_index.py` | 由要点建标签池（含 ≥0.95 保守去重） |
| `pick_important.py` | 从要点里挑「纠正类 / 硬约束」补进重点池 |
| `run-forever.ps1` | 把上面这些串成"每轮收尾跑一趟"的流水线 |

它们**不在本仓库**。要看思路，读 `DESIGN.zh-CN.md`。
